Cable Labeler — Privacy notice

Effective 30 August 2026 · Release 1.0 · Android

Cable Labeler keeps a catalogue of your physical cables on this device — a cable name, the two ends it runs between, an optional identifier code and a note — so you can search the list and work out which real cable is which, and record when a label was generated and applied. The Settings & privacy screen states it in the app: "Every cable, endpoint, note, photo, code and printed sheet is stored only on this device. Cable Labeler has no account and no server: nobody at this end can read your catalogue, and support cannot retrieve it for you."

There is no Cable Labeler account, no sign-in, no server, and no sync. The app does not control a printer and does not contact one; recording a reprint writes a local label-history entry only.

Stored on your device

Everything is written to a single private SQLite database, cable-labeler.db, in the app's own storage. It holds:

  • cable records — label, status, the connectors and role, endpoint A and B, location, owner, colour, length, note, locked-draft flag and timestamps;
  • your location names and their hierarchy;
  • identifier codes and their revisions and state;
  • a per-field change history, so you can see what a value used to be;
  • print jobs and the per-label snapshot rows behind them — template, fields, size, copies, state, application note and timestamps;
  • saved filter reports, and rows retained from earlier versions of the catalogue;
  • two preferences: your answer to the diagnostics question, and the last verified Pro entitlement.

The database is opened with SQLite's secure_delete enabled, so deleted rows are overwritten rather than left in place. If a cable photo or a generated label file is present, it is stored in the app's private document directory and referenced from the database.

Optional diagnostics

One switch, labelled "Send anonymous diagnostics", sits in Settings & privacy and governs both product analytics and crash reporting. It is off by default. If the stored answer is missing or unreadable, it is treated as off — consent is never assumed. The screen shows "On — counts and outcomes are sent." or "Off — nothing is sent.", and turning it off stops delivery immediately.

Analytics. The analytics code path exists but no analytics key is configured in this release, so no analytics events can leave the device in this build even if you turn the switch on. Were a key ever configured, the app would be limited to a fixed allow-list of eight event names — a five-record activation, a label generated, a scan resolved, a print allowance used, a capacity limit encountered, a purchase completed, a purchase restored, and a thirty-day search-and-scan return — carrying only a count, a broad size band (1–4, 5–19, 20–49, 50–199, 200+), an outcome, a source, a template name and a tier. Anything else is rejected outright: keys matching cable labels, endpoints, notes, codes, URIs, file paths, photos, owners or names are refused rather than sent. If that changes, this page and the Play Data safety declaration will say so before the build ships.

Crash reporting. Sentry is configured in this release and starts only if the same switch is on. It is set to send no personal information, no breadcrumbs, no screenshots, no view hierarchy and no failed-request bodies, with all performance sampling off. Before a report is sent, content-bearing fields are stripped, file paths and identifier codes are redacted, and the error message is replaced with the literal text "Application error". The report is tagged with the release com.cocobottom.cablelabeler@1.0.0+1. Sentry processes this in its European region.

Purchases

Google Play processes payment. RevenueCat receives an anonymous installation identifier and the store transaction and entitlement information the app needs to show the Pro product, unlock it, and restore it. This traffic happens when the app checks your entitlement at startup, when the Cable Labeler Pro screen opens and reads the store's current offering, and when you tap a buy or restore control. It carries no catalogue content. Cable Labeler never receives your payment-card details. Erasing your data is deliberately never reported to anyone.

Permissions

The app declares only internet access, vibration, and legacy external-storage access capped at Android 12. It requests no runtime permissions at all: no camera, no location, no contacts, no microphone. The shipped app has no photo-capture screen, no image picker and no code scanner.

Device backup

Android's own backup service is switched off for this app in the shipped manifest, so your catalogue is not copied into a Google account backup. That also means a lost, reset or replaced device takes the catalogue with it, and there is no copy anywhere to restore from.

Retention and deletion

Local content stays until you delete a cable with "Delete cable…", use "Erase everything" in Settings & privacy, or uninstall the app. There is no server-side copy to request, because nothing was ever uploaded. Deleting local data does not erase records that Google, RevenueCat or Sentry retain under their own policies. See the deletion page.

Security

The catalogue uses application-private storage and Android's own platform protections. No system is perfectly secure, and device loss, app removal or storage failure can make the catalogue unrecoverable.

Children and international processing

Cable Labeler is a tool for cataloguing physical cables and is not directed to children. Google, RevenueCat and Sentry may process data in countries other than yours under their published safeguards.
